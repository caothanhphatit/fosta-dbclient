- Elasticsearch and OpenSearch are now ready engines: a tree of indices, data streams and aliases with document counts, sizes and health; a document grid typed by the mapping with structured and Query DSL filters, from/size paging for small sets and `search_after` with a point in time beyond 10,000 documents; and **Mapping** as the design view.
- Grid edits on Elasticsearch and OpenSearch are checked with `if_seq_no` / `if_primary_term`: a document someone else changed or deleted since you loaded it is a conflict, and nothing of the save is written. An index can declare its key field in the mapping (`_meta.fosta.key`) so the grid sorts, ranges and edits by it.
- The Dev Tools console runs `METHOD /path` requests with a JSON or NDJSON body, shows a hits table and the JSON response per request, completes endpoints, index names, Query DSL keys and fields, and Stop cancels the request and its cluster tasks. ES|QL (Elasticsearch 8.11+) and SQL tabs stream typed tables.
- The safety rules classify console requests by method and path: searches and counts are reads, document APIs writes, mappings and templates DDL, and deleting an index, delete/update by query and cluster settings need a typed confirmation. Paths the client would rewrite (`..`, `#`) are refused, and grid filters cannot run scripts.
- Elasticsearch and OpenSearch errors show the server's error type, reason, cause chain and HTTP status, with the position of a parsing error in the editor.
