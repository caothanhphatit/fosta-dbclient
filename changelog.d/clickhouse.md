- ClickHouse is now a ready engine: databases with their tables, views, materialized views and dictionaries (a table shows its engine, rows and size on disk), typed browsing with column filters, a raw `WHERE` and keyset paging, query tabs that stream results and stop with `KILL QUERY`, and server errors with their code, position and the failing statement.
- ClickHouse edits are asynchronous mutations (`ALTER TABLE … UPDATE`, `DELETE FROM`), and the grid says so. They work on MergeTree tables only; every other table is read-only. A change is guarded by the values you loaded and fails with a conflict when the row changed, and a set with a conflict applies nothing; without transactions, a server failure halfway leaves the earlier changes applied, and the error says how many.
- ClickHouse has a Parts and mutations view per table (with Kill for a running mutation) and a Server view with the running queries (with Stop) and the query log with duration, memory and rows.
- DROP, TRUNCATE, `ALTER … DROP PARTITION`, `SYSTEM` and `KILL` statements need a typed confirmation under the default safety rules.
