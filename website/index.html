Why Fosta Studio

Fast where it counts, careful where it matters

A native client for developers who move between projects, engines and environments all day, and would rather not break production on the way.

  • ~9 MBinstaller download; a portable .exe needs no install
  • 11engines supported today
  • 2editions: desktop app and web (Docker)
  • 5+AI providers, from Claude and GPT to local models

  • Native, small and quick

    A Rust core in a Tauri 2 shell with a plain TypeScript UI and a virtualised grid. The installer is about 9 MB, and the app leaves your memory to the databases.

  • A view that fits each engine

    SQL tables open in an editable grid. Redis keys, Elasticsearch search, ClickHouse parts and Oracle PL/SQL each get a view of their own instead of being squeezed into rows.

  • Workspaces that open their own tunnels

    Each project or environment keeps its connections, tabs and startup tasks. Open it and kubectl port-forward starts, restarts when it drops, and stops when you quit.

  • Production stays read-only

    Every statement, on every engine, passes one gateway with rules per workspace. A Production workspace defaults to read-only, and risky statements ask for confirmation first.

  • An AI agent that knows your schema

    Ask in plain words. The agent explores tables and relations, writes and explains queries, opens the right view and reads task logs to help you debug. Use Claude, GPT, Gemini, Fosta or a local Ollama model.

  • Open source, desktop or Docker

    GPL-3.0, no account, no telemetry. A Windows desktop app, or a web edition that starts with one docker run.

Features

Built for the way you work with data

From the first query of the day to the last migration check, the everyday work stays quick, visible and under your control.

A query editor that keeps up

Syntax highlighting, a formatter and completion that knows your tables and columns, for SQL, MongoDB commands and Redis. Several statements per run; each tab keeps its own session, so BEGIN…COMMIT can span runs.

  • Every run lands in a searchable history that stays on your machine
  • Results open in the same grid as tables, ready to filter and export
  • Streaming results that show the first rows at once, and a Stop that really cancels on the server

Workspaces and startup tasks

Group connections, startup tasks and open tabs per project, customer or environment, then switch from the rail on the left or with Ctrl+1…9. Tabs of other workspaces stay open.

  • Run kubectl port-forward or any command when a workspace opens
  • Automatic restart with backoff when a tunnel drops, and live logs
  • Child processes are cleaned up when the app exits
  • Production workspaces with safety rules

A data grid made for editing

A virtualised grid that pages through large tables, with type badges under each column name so you always know what you are looking at.

  • Inline editing, inserts and deletes collected in a pending-changes bar
  • Apply the changes together, or discard them; a row someone else changed is a conflict, not an overwrite
  • WHERE filters and per-column filters, sorting
  • A record panel that follows foreign keys to related rows

Interactive ER diagrams

See how a database fits together. The diagram lays itself out automatically; drag tables around, zoom in, and export the result.

  • Automatic layout, drag and zoom
  • Export to SVG or PNG
  • Inferred links between MongoDB collections

A built-in AI agent for your databases

Ask in plain words. The agent looks up tables, columns and relations, writes and explains queries, fixes errors, and opens a table, a diagram or a new query tab for you. Every code block has Run, Insert and New tab buttons.

You stay in control. Run on a code block follows your workspace's safety rules, like any run of your own. The agent's own queries are read-only, and you can turn them off.

  • Bring your own model: Fosta, OpenAI, Gemini, Claude, or any OpenAI-compatible endpoint such as a local Ollama
  • Your key is stored in Windows Credential Manager and requests go straight from your machine to the provider
  • It sees metadata and what you share; the optional read-only query tool can read up to 50 rows, which go to your provider

Disclosure: Fosta, the default provider, is a separate AI API service run by the author of Fosta Studio. It is listed first for convenience only; nothing in Fosta Studio requires a Fosta account, and requests only go to the provider you configure.

  • Import & export

    Import CSV, TSV or JSON with column mapping. Export to CSV, CSV for Excel, JSON, SQL INSERT statements or Markdown.

  • MariaDB vector tools

    For MariaDB 11.7+: embedding search, column and index health checks, and recall of the vector index measured against exact search.

  • Connections, SSH and TLS

    Paste a connection string for any engine. Add an SSH tunnel with a jump host or agent, and TLS with your CA, a client certificate or a pinned fingerprint. Passwords stay in Credential Manager.

  • Cell editor

    Press Shift+Enter on a long value for a large editor with NULL, word wrap, and Format / Minify with validation for JSON.

Privacy & safety

Your data stays yours

Fosta Studio talks to your databases and to the AI provider you configure. Nothing else.

  • Local, portable config

    Workspaces, connections and tasks live in fosta-studio.json next to the executable. No secrets are written to it.

  • Windows Credential Manager

    Database passwords and AI keys are stored in the operating system's credential store, never in the config file.

  • No telemetry, no account

    The app does not phone home and does not need a sign-up. It is fully usable offline with local databases.

  • What the agent sees

    The model sees table and column metadata plus the editor text, errors and logs you choose to share. Statements run only when you run them. The optional read-only query tool reads up to 50 rows per query, which go to your provider; turn it off in Settings or per workspace.

  • Statement gateway

    Every statement, on every engine, passes through one gateway with rules per workspace: Open, Guarded, Read-only or Custom. A workspace marked Production defaults to Read-only, and relaxing a rule always comes with a loud warning.

Roadmap

Where it is heading

Planned work, roughly in order. Plans change; open an issue to discuss any of it.

  1. Engine depth

    Oracle without Instant Client, Redis Cluster and Sentinel, and more tools per engine.

  2. Data profiling & generation

    Column statistics and histograms; rule-based test data with preview before insert.

  3. Backup & restore

    Logical dumps built by the app, no external tools required.

  4. MongoDB beyond Compass

    A query bar with autocomplete, document views and an aggregation builder.

  5. Local database servers

    Create and run development servers without Docker or admin rights.

  6. Signed builds & sync

    Code-signed installers, winget and Scoop packages, and end-to-end encrypted sync between machines.

Contributing guide Architecture

Build from source

Prefer to build it yourself? You need Node 20+, Rust 1.88+ and the MSVC or GNU toolchain (toolchain details). 

> git clone https://github.com/caothanhphatit/fosta-dbclient.git
> cd fosta-dbclient
> npm install
> npm run tauri build -- --no-bundle

The result is src-tauri\target\release\fosta-studio.exe. Want to try the UI first? npm run dev previews it in a browser with sample data.
